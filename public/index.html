About This Project

ShopFlow is a CISS 340 database analytics project. Every record shown here is realistic, instructor-provided fictional data.

How data reaches this page

Browser → Netlify page → Netlify Function/API → Aiven MySQL → JSON → Browser. The browser never connects to the database. Each Netlify Function uses a read-only account (shopflow_reader, SELECT access only) and runs approved, parameterized queries over a verified TLS connection. The function returns JSON, and this page turns it into what you see.

The database

Seven tables: customers, products, orders, order_items, reviews, abandoned_carts and support_tickets. Customers place orders, and each order has order items that point to products. Reviews link a customer to a product. Abandoned carts and support tickets belong to a customer, and a ticket can optionally point to an order.

Cleaning before loading

  • The text "NULL" became a real NULL, and nothing missing was filled in.
  • Phone numbers were put in one format, emails were lower-cased, and dates became ISO dates.
  • TRUE/FALSE text became real Boolean values.
  • Parents were loaded before children, and the load finished with no orphan rows.

Selected results and how they were checked

  • Products: active products only. The count matches the notebook's count of active products.
  • Top Products: Delivered revenue (quantity × unit price). Matches the notebook's product performance query.
  • Customer Segments: Delivered revenue and orders by segment match the notebook's segmentation query. The Customers column counts all active customers in each segment, not only those who bought.
  • Revenue Analysis: Delivered revenue by category. The categories add up to the notebook's Delivered revenue total.
  • Order Status: counts match the notebook's fulfillment query. "Order value" adds up total_amount (including tax and shipping), so it is not revenue.

The complete analysis (all 10 queries and 5 interactive charts) is in the executed notebook. This site shows selected views only.
